# TincLink 管理后台资源授权：部署与回滚

## 范围与语义

后台仍先校验若依功能权限，再按稳定 ID 校验资源。超级管理员（`user_id=1`）可管理全部资源；普通后台账号默认没有 Tinc 资源授权。超级管理员在“系统管理 → 用户管理 → 网络资源授权”明确分配服务器或网络。服务器授权覆盖其现有和将来的网络及节点；单独网络授权只覆盖该网络及节点。普通账号不能转授资源。客户端节点接入码和 Access Agent 密钥不是后台账号授权，均保持原流程。

列表、导出和监控使用数据库范围过滤；详情、运行状态、创建、修改、轮换接入码、删除及旧路径在服务调用前校验 ID。批量删除先校验整批。网络所属服务器选择器只返回 ID、名称；只有整台服务器授权的账号能看到创建网络所需的分配范围。旧版管理员 ZIP 下载因文件名不含稳定 ID，只允许超级管理员使用。资源拒绝返回 HTTP 403，业务码 `TINC_RESOURCE_FORBIDDEN`。失效/删除账号不能通过旧会话继续访问资源。授权保存是完整替换事务；两组空数组才表示明确撤销全部资源。

## 上线前检查

1. 备份生产 MySQL、当前 Management JAR 和 Vue 静态目录；记录恢复位置与当前版本。确认备份可恢复。
2. 在生产库备份副本执行 [迁移脚本](../sql/20261011_tinc_resource_grants.sql)，核对表结构、联合主键和索引；查询现有 `sys_user.user_id`、`tinc_server.Id`、`tinc_network.id/server_id`，规划每个普通后台账号的授权。不要依据创建人、资源名自动回填。
3. 在维护窗口先执行该脚本，确认新表为空且可查询。**替换 JAR 前**，在服务器上运行只读预检：`bash deploy/server/preflight-management-schema.sh ry-tinc`。如果数据库账号需要独立的 MySQL option file，可将其绝对路径作为第二个参数；不要把密码写在命令行或脚本中。操作人还须核对该客户端连接的数据库主机/端口与 Spring 数据源一致：仅同名数据库不能证明是同一个实例。预检会核对目标库、授权表关键列、联合主键、索引和应用启动查询，任何失败都应保留旧 JAR 运行，不得通过跳过 `verifySchema()` 放行。此脚本不建表、不迁移数据、不替换 JAR。
4. 预检通过后才替换同一版本的 Management JAR 和 Vue 静态文件。新 JAR 启动时还会再次验证授权表必需列；不要只更新其中一端后直接交给普通账号使用。
5. 超级管理员登录用户管理页，按稳定 ID 分配 Server/Network。普通账号要同时拥有对应若依菜单/按钮功能权限。生产授权记录含操作者 ID 和时间；授予整台服务器会自动覆盖后续网络，需谨慎。

## 上线验收

- 超级管理员可查看既有 Server/Network/Node 和 Runtime，网络生产服务的 PID、接口与端口应保持原样。
- 空授权的普通后台账号在 Tinc 列表、导出、监控看不到资源；猜测其他 ID 的详情、运行状态、修改、删除与旧 API 路径返回 HTTP 403 + `TINC_RESOURCE_FORBIDDEN`。
- 授予一个网络后，只能查看/操作该网络及其节点；服务器选择器显示所属服务器名称，但服务器详情和其他网络拒绝。授予整台服务器后，该服务器下网络/节点可访问；仍需对应功能权限。
- 两个并发授权替换不会合并成意外范围。撤销授权后重新请求立即生效；如已打开页面，应刷新以更新旧列表。客户端接入码与 Agent 身份未被此操作撤销。
- 管理员账号被停用或逻辑删除后，旧登录态访问 Tinc 管理接口拒绝；Node 客户端链路按原契约回归。

## 回滚

若上线后异常，先恢复原 Management JAR 和 Vue 静态文件，再验证原接口及生产 Tinc 状态。新增授权表可暂时保留，不参与旧版本读取；不要通过删除生产 Tinc 表、密钥或 Runtime 回滚。若必须回退数据库，以预先验证过的备份和变更记录单独制定恢复操作。**此文档是部署步骤，提交代码不代表已在生产执行迁移或部署。**
