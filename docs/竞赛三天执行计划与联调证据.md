# 竞赛三天执行计划与联调证据

更新时间：2026-09-16（Asia/Shanghai）

## 目标与冻结边界

目标是完成“一台隔离测试网关 + 一台 Windows 客户端”的可重复演示闭环：登录、下载配置、上传公钥、网关应用公钥、启动 Tinc、握手、精确路由连通、停止并清理。

以下契约冻结，不在本轮修改：

- ZIP 只包含 `<netName>/tinc.conf` 和 `<netName>/hosts/server_master`；
- ZIP 不包含脚本、私钥、程序、动态库、Token、密码或说明文件；
- 客户端 `tinc.conf` 固定为 router/IPv4，并连接 `server_master`；
- 不重新引入 OS 字段，不由服务端向客户端下发启停脚本；
- 不停止、重启或修改生产 `new_network`；不输出 Token、密码、私钥或完整公钥。

## 三天执行计划

### Day 1：打通真实数据面

1. 冻结 ZIP/API 安全契约并完成基线测试。
2. 选定 `network1` 作为隔离测试网络；保留原配置备份，不复制、读取或改写私钥。
3. 将网关配置统一为 `Mode=router`、`Port=655`、`Interface=tinc1`，host 同步声明 655。
4. 将遗留手工 tincd 受控迁移到 `tinc@network1.service`，同时验证生产 `new_network` PID 不变。
5. 幂等放行 655/TCP 与 655/UDP 的 firewalld 运行时、永久规则。
6. 使用测试节点完成真实 login、config/download、key/upload；检查 ZIP 精确条目、网关 host 指纹与 HUP。
7. Windows 客户端启动 VPN，检查握手、`10.0.10.1/32` 精确路由、Ping 和 `connection=connected`；停止后检查清理。

### Day 2：稳定性和失败可诊断性

1. 连续执行 5 次“登录→配置→启动→连通→停止”，记录成功率和耗时。
2. 验证相同公钥重复上传、两个重复请求并发、active 网络重复 ensure。
3. 仅在隔离网络验证后端重启和 Agent 重启后的恢复；生产网络只读监测。
4. 验证 TCP/UDP、接口、地址或脚本异常能返回稳定业务码；不得通过停止生产网络制造故障。
5. 执行后端单元/集成测试和客户端现有自动化测试，保存测试数量和摘要。

### Day 3：演示固化和发布候选

1. 固定服务端 JAR、Agent、桌面端与 Tinc 二进制 SHA-256，整理安装/回滚步骤。
2. 制作演示前检查清单和 5 分钟演示脚本，准备脱敏日志与失败诊断截图。
3. 进行一次冷启动彩排和一次断网后的恢复彩排；明确云安全组仍需部署前人工确认。
4. 冻结发布候选，只修复 P0/P1 缺陷，不扩展插件平台或成熟 VPN 产品功能。
