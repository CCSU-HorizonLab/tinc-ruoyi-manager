## 一、问题概述

### 1.1 核心矛盾

当前 RuoYi 管理后台在创建/修改 Tinc VPN 网络和节点时，会通过 `TincConfigUtils` 将配置文件和密钥**写入 Java 后台进程所在的本地磁盘**（Linux: `/etc/tinc/<netName>/`，Windows: `D:/tinc/<netName>/`）。

但实际的 `tincd` 守护进程运行在 **另一台物理机**（即 `mange_server` 表中记录的那台 VPN 网关服务器）上。Java 后台只是通过 `MangeServer.serverIp` 知道了网关的 IP，却**从未把配置文件推送过去**。

结果就是：
- Java 后台本机有一份完整的 Tinc 配置
- 真正的 Tinc 网关服务器上什么都没有
- 客户端（Qt 客户端）下载的配置中包含 `ConnectTo = server_master`，指向的是网关服务器的公网 IP，但网关上的 `tincd` 根本没加载这些配置

### 1.2 具体影响

| 场景 | 影响 |
|------|------|
| **分离部署** | Java 后台在机器 A，Tinc 网关在机器 B — 配置永远不会到达网关 |
| **集群部署** | 多台 Java 节点各自维护独立的 `/etc/tinc/` 副本，数据不一致 |
| **重启/迁移** | Java 节点重启后本地临时文件丢失（如果有的话），配置无法恢复 |

## 二、现有代码流程分析

### 2.1 创建网络流程

```
用户点击"新增网络"
  → TincNetworkMangeController.add()
    → TincNetworkMangeServiceImpl.insertTincNetworkMange()
      1. DB 写入 tinc_network_mange 记录
      2. 读取 MangeServer 表获取 realPublicIp（网关真实 IP）
      3. TincConfigUtils.initNetworkEnv(netName)        → 本地 mkdirs
      4. RsaUtils.generateKeys()                        → 在 Java 进程内生成 RSA 4096 密钥对
      5. TincConfigUtils.createTincConf(...)            → 本地写 tinc.conf
      6. TincConfigUtils.createTincUpAndDown(...)       → 本地写 tinc-up/down 脚本
      7. TincConfigUtils.createHostFile(...)             → 本地写 hosts/server_master
      8. TincConfigUtils.createPrivateKey(...)           → 本地写 rsa_key.priv

  问题：步骤 3-8 全部写入 Java 进程所在机器的本地磁盘
        realPublicIp（网关 IP）只被写进了 hosts/server_master 的 "Address = xxx" 行
        从未用来 SSH/SCP 推送这些文件到目标网关
```

### 2.2 客户端下载配置流程

```
Qt 客户端请求 /api/tinc/client/config/download
  → TincClientApiController.downloadConfig()
    1. 从 DB 查节点信息（node_ip 等）
    2. 从 DB 查网络信息
    3. TincConfigUtils.readHostFile(netName, "server_master")  → 读本地文件！
    4. 在内存中动态拼接 tinc.conf、tinc-up/down 等内容
    5. 打包成 ZIP 返回给客户端

  问题：步骤 3 读取的是 Java 后台本地的文件
        如果网关未推送过，读到的 server_master host 文件是旧的或不存在
```

### 2.3 公钥上传流程

```
Qt 客户端上传公钥 /api/tinc/client/key/upload
  → TincClientApiController.uploadKey()
    1. 查 DB 验证节点和网络
    2. 正则提取 PEM 公钥块
    3. TincConfigUtils.createHostFile(netName, nodeName, subnet, cleanPubKey) → 写本地！
    4. TincConfigUtils.readHostFile(netName, "server_master")                 → 读本地！
    5. 更新节点状态为"已配置"

  问题：步骤 3 把客户端公钥写到了 Java 后台本地，而不是网关服务器
        网关上的 tincd 需要在 hosts/ 目录下看到所有节点的公钥才能建立连接
```

## 三、解决方案设计

### 3.1 总体架构

```
┌──────────────────────────────────────┐
│         RuoYi 管理后台 (Java)         │
│                                      │
│  Controller → Service → Mapper (DB)  │
│                    ↓                 │
│            TincConfigTransport        │  ← 新增：传输抽象层接口
│                    ↓                 │
│  ┌──────────────────────────────┐    │
│  │  SshTincConfigTransport      │    │  ← 默认实现：JSch SSH/SCP
│  │  (JSch + SCP + Exec)        │    │
│  └──────────────┬───────────────┘    │
└─────────────────┼────────────────────┘
                  │  SSH/SCP (Port 22)
                  ↓
┌─────────────────┼────────────────────┐
│  Tinc VPN 网关服务器                   │
│  (MangeServer.serverIp)              │
│                                      │
│  /etc/tinc/<netName>/                │
│    ├── tinc.conf                     │
│    ├── tinc-up / tinc-down           │
│    ├── rsa_key.priv                  │
│    └── hosts/                        │
│         ├── server_master            │
│         ├── node_a                   │
│         ├── node_b                   │
│         └── ...                      │
│                                      │
│  推送完成后执行:                       │
│    tincd -n <netName> -kHUP          │
│    (或 systemctl reload tinc@<name>) │
└──────────────────────────────────────┘
```

### 3.2 设计原则

1. **接口抽象**：`TincConfigTransport` 接口抽象配置传输，支持多种实现（SSH / 本地 / Agent / MQ）
2. **本地保留副本**：`TincConfigUtils` 仍然写本地一份（用于调试、审计和客户端下载），但推送逻辑独立
3. **事务一致性**：DB 写入成功 + 推送成功 = 提交；推送失败 = 回滚 DB 事务
4. **可配置**：通过 `application.yml` 选择传输实现，单机部署可选 "local" 模式跳过推送
5. **向后兼容**：不改变现有 Controller API 签名，只改造 Service 层和工具类

### 3.3 传输模式对比

| 模式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| **local** | 单机部署（Java 和 tincd 同机） | 零配置，直接写本地 | 不支持分离/集群 |
| **ssh**（推荐） | 分离部署，标准 Linux 网关 | 无需在网关安装额外软件 | 需要 SSH 凭证管理 |
| **agent** | 复杂场景，多网关集群 | 解耦，可扩展 | 需额外部署 Agent 服务 |
| **nfs** | 同机房共享存储 | 最简单 | 单点故障，跨机房不适用 |

首期推荐实现 **local + ssh** 两种模式。

### 步骤 3：新增 `TincConfigTransport` 接口

**新建文件**：`ruoyi-common/src/main/java/com/ruoyi/common/transport/TincConfigTransport.java`

```java
package com.ruoyi.common.transport;

/**
 * Tinc 配置文件传输抽象层
 * 
 * 将生成的配置文件和密钥推送到实际运行 tincd 的 VPN 网关服务器上，
 * 解决管理后台与 Tinc 网关分离部署 / 集群部署时的配置同步问题。
 */
public interface TincConfigTransport {

    /**
     * 推送一个配置文件到目标网关
     * 
     * @param targetHost  目标网关 IP 地址
     * @param remotePath  目标网关上的绝对路径（如 /etc/tinc/mynet/tinc.conf）
     * @param content     文件内容（纯文本）
     * @param executable  是否为可执行脚本（tinc-up/down 需要 +x）
     */
    void pushFile(String targetHost, String remotePath, String content, boolean executable);

    /**
     * 推送整个目录到目标网关（如 hosts/ 目录）
     *
     * @param targetHost 目标网关 IP 地址
     * @param remoteDir  目标网关上的目录路径
     * @param files      文件名 → 文件内容的映射（相对路径）
     */
    void pushDirectory(String targetHost, String remoteDir, java.util.Map<String, String> files);

    /**
     * 重载目标网关上指定网络的 tincd 配置
     * 等效于: tincd -n <netName> -kHUP
     */
    void reloadTinc(String targetHost, String netName);

    /**
     * 重启目标网关上指定网络的 tincd 服务（systemd 方式）
     */
    void restartTinc(String targetHost, String netName);
}
```

### 步骤 4：实现 `SshTincConfigTransport`

**新建文件**：`ruoyi-common/src/main/java/com/ruoyi/common/transport/SshTincConfigTransport.java`

核心逻辑：

```java
package com.ruoyi.common.transport;

import com.jcraft.jsch.*;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.io.ByteArrayInputStream;
import java.nio.charset.StandardCharsets;
import java.util.Map;

/**
 * 基于 JSch SSH/SCP 的 Tinc 配置传输实现
 * 
 * 通过 SSH 协议将配置文件推送到远程 Tinc VPN 网关服务器，
 * 并在推送完成后重载 tincd 服务。
 */
public class SshTincConfigTransport implements TincConfigTransport {

    private static final Logger log = LoggerFactory.getLogger(SshTincConfigTransport.class);

    /** SSH 连接超时 (毫秒) */
    private int connectTimeout = 10000;

    /** 全局默认 SSH 端口（当 MangeServer 未配置时使用） */
    private int defaultSshPort = 22;

    /** 全局默认 SSH 用户 */
    private String defaultSshUser = "root";

    /** 全局默认 SSH 私钥路径 */
    private String defaultSshKeyPath;

    /** 全局默认 SSH 密码 */
    private String defaultSshPassword;

    // --- 构造函数 + setter 注入（Spring Bean 配置） ---

    public SshTincConfigTransport() {}

    public void setConnectTimeout(int connectTimeout) { this.connectTimeout = connectTimeout; }
    public void setDefaultSshPort(int defaultSshPort) { this.defaultSshPort = defaultSshPort; }
    public void setDefaultSshUser(String defaultSshUser) { this.defaultSshUser = defaultSshUser; }
    public void setDefaultSshKeyPath(String defaultSshKeyPath) { this.defaultSshKeyPath = defaultSshKeyPath; }
    public void setDefaultSshPassword(String defaultSshPassword) { this.defaultSshPassword = defaultSshPassword; }

    /**
     * 获取 SSH Session
     * 优先使用 MangeServer 表中配置的凭证，否则使用全局默认值
     */
    private Session getSession(String host, Integer port, String user,
                                String keyPath, String password) throws JSchException {
        JSch jsch = new JSch();

        int actualPort = (port != null) ? port : defaultSshPort;
        String actualUser = (user != null && !user.isEmpty()) ? user : defaultSshUser;

        // 私钥认证优先
        String actualKeyPath = (keyPath != null && !keyPath.isEmpty()) ? keyPath : defaultSshKeyPath;
        if (actualKeyPath != null && !actualKeyPath.isEmpty()) {
            jsch.addIdentity(actualKeyPath);
        }

        Session session = jsch.getSession(actualUser, host, actualPort);
        session.setTimeout(connectTimeout);

        // 如果没有配置私钥，则使用密码认证
        String actualPassword = (password != null && !password.isEmpty()) ? password : defaultSshPassword;
        if ((actualKeyPath == null || actualKeyPath.isEmpty()) && actualPassword != null) {
            session.setPassword(actualPassword);
        }

        // 跳过 host key 校验（生产环境应该配置 known_hosts）
        session.setConfig("StrictHostKeyChecking", "no");

        session.connect(connectTimeout);
        return session;
    }

    @Override
    public void pushFile(String targetHost, String remotePath, String content, boolean executable) {
        log.info("开始推送文件到 {} : {}", targetHost, remotePath);
        Session session = null;
        ChannelSftp sftp = null;
        try {
            session = getSession(targetHost, null, null, null, null);
            sftp = (ChannelSftp) session.openChannel("sftp");
            sftp.connect(connectTimeout);

            // 确保父目录存在
            String parentDir = remotePath.substring(0, remotePath.lastIndexOf('/'));
            try { sftp.mkdir(parentDir); } catch (Exception ignored) {}
            try { sftp.mkdir(parentDir + "/hosts"); } catch (Exception ignored) {}

            // 推送文件内容
            ByteArrayInputStream bis = new ByteArrayInputStream(
                    content.replace("\r\n", "\n").getBytes(StandardCharsets.UTF_8));
            sftp.put(bis, remotePath, ChannelSftp.OVERWRITE);
            bis.close();

            // 设置可执行权限
            if (executable) {
                sftp.chmod(0755, remotePath);
            }

            log.info("文件推送成功: {} -> {}:{}", remotePath, targetHost, remotePath);
        } catch (Exception e) {
            log.error("推送文件失败: {} -> {}", remotePath, targetHost, e);
            throw new RuntimeException("无法推送配置文件到 Tinc 网关: " + e.getMessage(), e);
        } finally {
            if (sftp != null && sftp.isConnected()) sftp.disconnect();
            if (session != null && session.isConnected()) session.disconnect();
        }
    }

    @Override
    public void pushDirectory(String targetHost, String remoteDir, Map<String, String> files) {
        for (Map.Entry<String, String> entry : files.entrySet()) {
            String filePath = remoteDir + "/" + entry.getKey();
            boolean isExec = filePath.endsWith("tinc-up") || filePath.endsWith("tinc-down");
            pushFile(targetHost, filePath, entry.getValue(), isExec);
        }
    }

    @Override
    public void reloadTinc(String targetHost, String netName) {
        String cmd = "tincd -n " + netName + " -kHUP";
        execCommand(targetHost, cmd);
    }

    @Override
    public void restartTinc(String targetHost, String netName) {
        String cmd = "systemctl restart tinc@" + netName;
        execCommand(targetHost, cmd);
    }

    private void execCommand(String targetHost, String command) {
        log.info("在网关 {} 上执行命令: {}", targetHost, command);
        Session session = null;
        ChannelExec exec = null;
        try {
            session = getSession(targetHost, null, null, null, null);
            exec = (ChannelExec) session.openChannel("exec");
            exec.setCommand(command);
            exec.setInputStream(null);
            exec.setErrStream(System.err);
            exec.connect(connectTimeout);

            // 等待命令执行完成
            while (!exec.isClosed()) {
                try { Thread.sleep(500); } catch (InterruptedException ignored) {}
            }

            int exitStatus = exec.getExitStatus();
            log.info("命令执行完成 [{}]: exit={}", targetHost, exitStatus);
            if (exitStatus != 0) {
                log.warn("远程命令返回非零退出码 [{}]: exit={}, cmd={}", targetHost, exitStatus, command);
            }
        } catch (Exception e) {
            log.error("远程命令执行失败 [{}]: {}", targetHost, command, e);
            throw new RuntimeException("无法在 Tinc 网关执行命令: " + e.getMessage(), e);
        } finally {
            if (exec != null && exec.isConnected()) exec.disconnect();
            if (session != null && session.isConnected()) session.disconnect();
        }
    }
}
```

### 步骤 5：新增 `LocalTincConfigTransport`（本地模式，向后兼容）

**新建文件**：`ruoyi-common/src/main/java/com/ruoyi/common/transport/LocalTincConfigTransport.java`

```java
package com.ruoyi.common.transport;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.io.File;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.util.Map;

/**
 * 本地文件传输实现（向后兼容单机部署场景）
 * 
 * 直接将配置文件写入 Java 进程所在机器的本地磁盘。
 * 适用于管理后台和 Tinc 网关运行在同一台机器上的场景。
 */
public class LocalTincConfigTransport implements TincConfigTransport {

    private static final Logger log = LoggerFactory.getLogger(LocalTincConfigTransport.class);

    private final String basePath;

    public LocalTincConfigTransport(String basePath) {
        this.basePath = basePath;
    }

    @Override
    public void pushFile(String targetHost, String remotePath, String content, boolean executable) {
        // 本地模式下忽略 targetHost，直接写本地 basePath
        File file = new File(remotePath);
        try {
            if (file.getParentFile() != null && !file.getParentFile().exists()) {
                file.getParentFile().mkdirs();
            }
            String safeContent = content.replace("\r\n", "\n");
            Files.write(file.toPath(), safeContent.getBytes(StandardCharsets.UTF_8));

            if (executable) {
                file.setExecutable(true, false);
            }
            log.info("本地配置文件写入成功: {}", remotePath);
        } catch (IOException e) {
            log.error("本地配置文件写入失败: {}", remotePath, e);
            throw new RuntimeException("生成配置失败: " + e.getMessage(), e);
        }
    }

    @Override
    public void pushDirectory(String targetHost, String remoteDir, Map<String, String> files) {
        for (Map.Entry<String, String> entry : files.entrySet()) {
            String filePath = remoteDir + "/" + entry.getKey();
            boolean isExec = filePath.endsWith("tinc-up") || filePath.endsWith("tinc-down");
            pushFile(targetHost, filePath, entry.getValue(), isExec);
        }
    }

    @Override
    public void reloadTinc(String targetHost, String netName) {
        log.info("本地模式：跳过远程 tincd 重载，请手动执行 tincd -n {} -kHUP", netName);
    }

    @Override
    public void restartTinc(String targetHost, String netName) {
        log.info("本地模式：跳过远程 tincd 重启，请手动执行 systemctl restart tinc@{}", netName);
    }
}
```

### 步骤 6：改造 `TincConfigUtils`

**修改文件**：`ruoyi-common/src/main/java/com/ruoyi/common/utils/TincConfigUtils.java`

核心改动：
1. 引入 `TincConfigTransport` 依赖（静态注入，由 Spring 在启动时设置）
2. 每个写入方法增加对应的 `pushToGateway()` 调用
3. 新增 `setTransport()` 静态方法供 Spring 注入
4. 方法签名增加 `gatewayIp` 参数

详细的改造后代码：

```java
package com.ruoyi.common.utils;

import com.ruoyi.common.transport.TincConfigTransport;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.io.File;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;

public class TincConfigUtils {

    private static final Logger log = LoggerFactory.getLogger(TincConfigUtils.class);

    /** 传输层 — 由 Spring 在启动时通过 setTransport() 注入 */
    private static TincConfigTransport transport;

    /** 基路径：Linux /etc/tinc，Windows D:/tinc */
    private static final String BASE_PATH = System.getProperty("os.name").toLowerCase().startsWith("win")
            ? "D:/tinc"
            : "/etc/tinc";

    /**
     * Spring 容器启动时调用，注入传输层实现
     */

        return BASE_PATH;

    // -------------------- 本地写入（保留副本） --------------------

    private static void writeToFile(String netName, String fileName, String content, boolean isScript) {
        String fullPath = BASE_PATH + "/" + netName + "/" + fileName;
        File file = new File(fullPath);
        try {
            if (file.getParentFile() != null && !file.getParentFile().exists()) {
                file.getParentFile().mkdirs();
            }
            String safeContent = content.replace("\r\n", "\n");
            Files.write(file.toPath(), safeContent.getBytes(StandardCharsets.UTF_8));
            if (isScript && !System.getProperty("os.name").toLowerCase().startsWith("win")) {
                file.setExecutable(true, false);
            }
            log.info("本地配置文件写入成功: {}", fullPath);
        } catch (IOException e) {
            log.error("无法写入文件: {}", fullPath, e);
            throw new RuntimeException("生成配置失败: " + e.getMessage());
        }
    }

    /**
     * 推送一个文件到远程网关（如果 transport 已配置）
     */
    private static void pushToGateway(String gatewayIp, String netName, String fileName,
                                       String content, boolean executable) {
        if (transport != null && gatewayIp != null && !gatewayIp.isEmpty()) {
            String remotePath = BASE_PATH + "/" + netName + "/" + fileName;
            transport.pushFile(gatewayIp, remotePath, content, executable);
        }
    }

    // -------------------- 公开 API（新增 gatewayIp 参数） --------------------

    public static void createTincConf(String gatewayIp, String netName, String nodeName, String connectToNode) {
        StringBuilder sb = new StringBuilder();
        sb.append("Name = ").append(nodeName).append("\n");
        sb.append("Interface = tinc0").append("\n");
        if (connectToNode != null && !connectToNode.trim().isEmpty()) {
            sb.append("ConnectTo = ").append(connectToNode).append("\n");
        }
        sb.append("Mode = switch").append("\n");

        String content = sb.toString();
        writeToFile(netName, "tinc.conf", content, false);
        pushToGateway(gatewayIp, netName, "tinc.conf", content, false);
    }

    public static void createTincUpAndDown(String gatewayIp, String netName, String virtualIp) {
        String linuxUp = "#!/bin/sh\nifconfig $INTERFACE " + virtualIp + " netmask 255.255.255.0\n";
        writeToFile(netName, "tinc-up", linuxUp, true);
        pushToGateway(gatewayIp, netName, "tinc-up", linuxUp, true);

        String linuxDown = "#!/bin/sh\nifconfig $INTERFACE down\n";
        writeToFile(netName, "tinc-down", linuxDown, true);
        pushToGateway(gatewayIp, netName, "tinc-down", linuxDown, true);

        String winUp = "@echo off\r\nnetsh interface ipv4 set address name=\"%INTERFACE%\" source=static address="
                + virtualIp + " mask=255.255.255.0\r\n";
        writeToFile(netName, "tinc-up.bat", winUp, false);
        pushToGateway(gatewayIp, netName, "tinc-up.bat", winUp, false);

        String winDown = "@echo off\r\nnetsh interface ipv4 set address name=\"%INTERFACE%\" source=dhcp\r\n";
        writeToFile(netName, "tinc-down.bat", winDown, false);
        pushToGateway(gatewayIp, netName, "tinc-down.bat", winDown, false);
    }

    public static void createHostFile(String gatewayIp, String netName, String nodeName,
                                       String subnet, String publicKey) {
        createHostFile(gatewayIp, netName, nodeName, subnet, null, publicKey);
    }

    public static void createHostFile(String gatewayIp, String netName, String nodeName,
                                       String subnet, String publicIp, String publicKey) {
        StringBuilder sb = new StringBuilder();
        if (publicIp != null && !publicIp.isEmpty()) {
            sb.append("Address = ").append(publicIp).append("\n");
        }
        sb.append("Subnet = ").append(subnet).append("\n\n");
        sb.append(publicKey);

        String content = sb.toString();
        writeToFile(netName, "hosts/" + nodeName, content, false);
        pushToGateway(gatewayIp, netName, "hosts/" + nodeName, content, false);
    }

    public static void createPrivateKey(String gatewayIp, String netName, String privateKey) {
        writeToFile(netName, "rsa_key.priv", privateKey, false);
        pushToGateway(gatewayIp, netName, "rsa_key.priv", privateKey, false);
    }

    public static String readHostFile(String netName, String nodeName) {

        } catch (IOException e) {
            throw new RuntimeException("读取配置文件失败");
        }
    }
```

```java
package com.ruoyi.common.config;

import com.ruoyi.common.transport.LocalTincConfigTransport;
import com.ruoyi.common.transport.SshTincConfigTransport;
import com.ruoyi.common.transport.TincConfigTransport;
import com.ruoyi.common.utils.TincConfigUtils;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class TincTransportConfig {

    private static final Logger log = LoggerFactory.getLogger(TincTransportConfig.class);

    @Value("${tinc.transport.mode:local}")
    private String transportMode;

    @Value("${tinc.transport.ssh.default-port:22}")
    private int defaultSshPort;

    @Value("${tinc.transport.ssh.default-user:root}")
    private String defaultSshUser;

    @Value("${tinc.transport.ssh.default-key-path:}")
    private String defaultSshKeyPath;

    @Value("${tinc.transport.ssh.default-password:}")
    private String defaultSshPassword;

    @Value("${tinc.transport.ssh.connect-timeout:10000}")
    private int connectTimeout;

    @Bean
    public TincConfigTransport tincConfigTransport() {
        TincConfigTransport transport;

        if ("ssh".equalsIgnoreCase(transportMode)) {
            log.info("=== Tinc 配置传输模式: SSH 远程推送 ===");
            SshTincConfigTransport sshTransport = new SshTincConfigTransport();
            sshTransport.setDefaultSshPort(defaultSshPort);
            sshTransport.setDefaultSshUser(defaultSshUser);
            sshTransport.setDefaultSshKeyPath(defaultSshKeyPath);
            sshTransport.setDefaultSshPassword(defaultSshPassword);
            sshTransport.setConnectTimeout(connectTimeout);
            transport = sshTransport;
        } else {
            log.info("=== Tinc 配置传输模式: 本地文件写入（单机部署）===");
            String basePath = System.getProperty("os.name").toLowerCase().startsWith("win")
                    ? "D:/tinc"
                    : "/etc/tinc";
            transport = new LocalTincConfigTransport(basePath);
        }

        // 注入到 TincConfigUtils 静态方法中
        TincConfigUtils.setTransport(transport);
        return transport;
    }
}
```

## 七、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| SSH 私钥泄露 | 网关被未授权访问 | 私钥放在 JAR 包外部，只通过文件路径引用；每台网关独立密钥 |
| 推送失败 | DB 写入成功但网关无配置 | Service `@Transactional` + 推送失败抛 RuntimeException → 回滚 DB |
| 防火墙阻断 SSH 22 | 推送永远失败 | 启动前检查网络可达性；SSH 端口可通过 mange_server 表逐台覆盖 |
| tincd reload 失败 | 新配置不生效 | `execCommand()` 记录日志 + 抛异常，不会静默跳过 |
| 高并发写入 | 同一文件的并发推送 | `TincConfigUtils` 操作自带覆盖语义，SCP OVERWRITE 模式，幂等安全 |
| JSch 版本兼容 | 老版本 JSch 不支持新算法 | 锁定 0.1.55 版本，经充分测试 |
